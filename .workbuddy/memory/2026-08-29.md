# 2026-08-29

## CMDCam：跟踪镜头俯仰跟随 + 可调参数 + 命令树统一（基于 ba143d7）

用户实机反馈三点：镜头不跟随实体俯仰角、镜头远近与 FOV 无参数、start/play 两个同义词管两套镜头系统不合理。

### 命令树（最终形态）
```
/cam-server start path <scene> <players> [duration] [loop]
/cam-server start tracking <scene> <target> <players> [duration] [distance_scale] [fov] [damping] [pitch_follow]
/cam-server start preset closeup|shoulder <target> <players> [duration] [distance] [fov] [damping] [pitch_follow]
```
旧命令 `play` / `start <scene> <target> <players>` / `closeup` / `shoulder` 保留为转发别名并提示弃用（`scene.start.deprecated`）。
参数为位置参数，从左到右；越界直接报错（lang key `scene.tracking.invalid_*`），不静默 clamp。

### 新增文件
- `common/scene/tracking/TrackingOptions.java`：统一运行配置，字段为 boxed `Double`，null = 未提供；`validate()` 抛带参数的 SceneException；NBT 序列化。
- `common/scene/tracking/CamPreset.java`：预设常量表（offset/lookAhead/lookHeight/fov/distance/heightFactor/dampingMs/pitchFollow），服务端与客户端共用，避免服务端加载客户端类。
- `common/scene/tracking/SmoothedTargetPose.java`：毫秒半衰期指数平滑，帧率无关；角度用 `Mth.rotLerp` 环绕插值；首帧直接吸附；目标丢失时 `skipFrame()`。
- `common/scene/mode/FollowPathMode.java`（注册 id `tracking`）：把已保存路径的控制点当局部偏移，旋转用「当前 yaw - 起始 yaw」的 delta 叠加到作者录制的绝对旋转上。

### 关键实现要点
- `CamTargetPose.localToWorld(x,y,z,yaw,pitch)`：先 pitch 后 yaw。推导出的正确符号是
  `pitchedY = y*cos(p) + z*sin(p)`、`pitchedZ = -y*sin(p) + z*cos(p)`（p 为 MC pitch，负值抬头）。
  效果：抬头时身后的摄影机下沉、身前的摄影机上升，与"绕头部公转"一致。
- `appliedPitch = clamp(smoothedPitch * pitchFollow, -75, 75)`；摄影机最终朝向始终重新 `lookAt(cameraPos, lookPos)`，不直接继承目标 pitch。
- 预设的 `distance` 是**缩放**作者录制的 offset（`scale = distance / preset.distance`），不是替换，这样 `smoothBeginning` 的入场插值仍然成立。
- shoulder 基准 offset 从 `(0.8, 0.4, 1.3)` 改为 `(0.8, 0.4, 1.8)`，让 `distance` 语义自洽。
- `tracking` 的 `fov` 语义：给值则覆盖全部控制点，不给则保留模板自身的 zoom 动画。
- 服务端只传字符串 + `CompoundTag optionsNbt`，绝不实例化 CamMode（`StartCloseupPacket`）。
- `CamScene.trackingOptions` 新字段，`bindTracking(UUID, TrackingOptions)` 重载；`set()`/`copy()` 同步复制。

### 坑
- CreativeCore 的 `Vec3d`/`VecNd` 只有 `set(Vec3d)`，没有 `set(double,double,double)`，要直接赋值 x/y/z。
- Brigadier 1.1.8 的 `CommandContext.getArgument` 有 `PRIMITIVE_TO_WRAPPER`，`getArgument(name, long.class)` 可用。
- `SceneException` 原来不支持参数，已加 `Object... args` 与 `getComponent()`；全部旧调用点改成 `e.getComponent()`。
- 编译命令：`./gradlew compileJava --offline`（可离线，已验证通过）。

### 行为变更（需告知用户）
- 默认加了阻尼（closeup 250ms / shoulder 350ms），镜头比之前"跟手"更软；想要旧手感用 `damping 0`。
- 旧 `start <scene> <target> <players>` 现在要求场景带跟随目标（相对控制点），否则报 `scene.tracking.absolute` 拒绝执行。

### 待用户实机确认（唯一未定稿的判断点）

### refmap 增量编译事故（14:5x 崩溃根因）
- 崩溃栈落在 KubeJS 的 `GeneratedClientResourcePack.generate`，但真因是 CMDCam 的 `EntitySelectorMixin` 的 `@Shadow checkPermissions` 对不上运行环境 srg 名 `m_121168_`。
- 根因：多次增量编译导致 AP 生成的 refmap 漏掉 `EntitySelectorMixin` 整个条目（其他 4 个 mixin 正常）。**refmap 不入库**，每次 clean 全量构建会正确重新生成。
- 教训：改完 mixin 相关代码后必须 `rm -rf build/classes build/tmp/compileJava build/libs` 再 `./gradlew jar --offline` 全量重建，否则部署包会崩。
